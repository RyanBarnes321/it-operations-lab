# v1.0.0 release notes — prepared, not tagged

The IT Operations & Automation Lab demonstrates operating a private Debian/Docker
monitoring stack alongside backend application engineering: host observability,
network diagnostics, incident handling, controlled changes and recovery evidence.
No new infrastructure is introduced by this handoff.

## Included scope

- Grafana 13.3.1, Prometheus 2.55.1, Node Exporter 1.8.2 and Blackbox Exporter 0.27.0.
- Provisioned six-panel dashboard with seven expressions, seven scrape targets,
  four availability probes and three tested alert rules.
- Bash diagnostics and PowerShell 7 endpoint diagnostics with negative-input tests.
- Attributed historical incidents and isolated failure simulations.
- Configuration/state backup runbooks, encrypted off-device workflow and isolated
  Grafana/Prometheus restore harness with historical query checks.
- Fresh-host instructions, security review, limitations, roadmap and evidence index.

User-executed acceptance reports nine of nine Windows cases passed (exit 0), six
functioning dashboard panels, an encrypted Windows round trip matching the original
archive SHA-256, isolated application restoration, and successful recovery using a
passphrase-encrypted USB identity copy. This final session did not execute Windows
actions or inspect private recovery material. The screenshot and raw Windows runner
JSON are missing; only the attributed report and returned restore JSON are available.

## Release holds

Historical runbooks retain an unnecessary private LAN address. Current instructions
are sanitized, but publication remains stopped pending approved history cleanup
and repeat audit. Final live validation is also outstanding: execution-environment
restrictions denied Docker and loopback socket access. Compose/source checks passed.
See [security review](../SECURITY.md), [evidence](../TEST-EVIDENCE.md) and
[release checklist](../RELEASE-CHECKLIST.md).

No `v1.0.0` tag existed at handoff; none was created because mandatory checks remain.
There is no application/package version manifest to update. The planned release
identifier is `v1.0.0`; no completed-release marker was added.

## Accepted limitations

Single host, defective battery, manual LUKS unlock, no automatic power restoration,
deferred centralized logging, local-only alerts, manual backups without guaranteed
RPO/RTO, and no independently verified offsite storage. Full details:
[known limitations](../LIMITATIONS.md). These do not by themselves block the lab release.

## Local tag procedure after holds close

Rerun validation and effective binding/authentication checks from an authorized
host session, review rewritten history, update this status and the checklist,
commit the acceptance record, and verify a clean tree. Recheck the tag namespace
immediately before creating an annotated tag; do not overwrite an existing tag.

```sh
git status --porcelain
git tag --list v1.0.0
# Continue only if the tree is clean, the tag is absent, and all gates are passed.
git tag -a v1.0.0 -m 'IT Operations & Automation Lab v1.0.0'
git rev-parse HEAD
git rev-parse 'v1.0.0^{commit}'
```

Tag creation is local. Creating a GitHub repository or pushing code/tags requires
explicit user authorization; no remote creation or push is part of this handoff.
